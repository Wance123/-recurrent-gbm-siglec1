# SIGLEC1 associated myeloid remodeling in recurrent glioblastoma

Analysis code for the revised manuscript **Cross cohort transcriptomic assessment of SIGLEC1 as a candidate marker of myeloid remodeling in recurrent glioblastoma**.

This release contains discovery preprocessing, doublet and annotation diagnostics, patient/specimen-level comparisons, external tissue and nuclear validation, exploratory network perturbation, and scientific plotting scripts. Complete derived numerical outcomes, including nonsignificant comparisons, are retained in the accompanying supplementary materials, not uploaded here. Raw expression matrices, specimen-level tables, confidential correspondence and manuscript files are not distributed here.

## Quick numerical verification

Use Python 3.11 or later in a fresh environment:

```bash
python -m pip install -r requirements-statistics.txt
python verify_release.py
```

Before running verification, place the accompanying supplementary CSV tables in the directory layout in INPUTS.md. These tables are included in the reviewer code-and-data companion folder, not in the public repository. The verification recomputes two-sided rank-test P values and BH correction from those derived measurements and checks myeloid-label concordance arithmetic. It does **not** rerun alignment, raw matrix reconstruction, integration, or virtual knockout. A successful check is not independent biological replication.

## Source data and input layout

See [INPUTS.md](INPUTS.md) for exact public sources and required files. Raw matrices are intentionally excluded. The original project directory structure is preserved. All original absolute research paths have been replaced with `portable_paths.py` controls; analytical formulas, thresholds and random seeds are unchanged. Set `JOB34_PROJECT_ROOT` to the cloned repository root. Input-location overrides include `JOB34_GSE174554_METADATA`, `JOB34_GSE174554_RAW`, `JOB34_CARE_METADATA`, `JOB34_CARE_RAW`, `JOB34_CGGA693`, `JOB34_CGGA325`, and `JOB34_AUTHOR_WORKSPACE`.

Run from the repository root. For the R scripts, also set `JOB34_ROOT` to the same root and set the relevant input overrides explicitly. Each discovery preprocessing script has `--help` for the exact file arguments. Do not run every historical script sequentially without checking its input/output contract.

## Analysis order

1. Audit GEO records, sample eligibility and matrices with `scripts/01` through `scripts/05`.
2. Build the discovery AnnData matrix and per-specimen Scrublet outputs with `scripts/06`; build the integrated atlas with `scripts/07`, inspect/recluster with `scripts/08`, and screen expression-derived CNV with `scripts/09`. These scripts require the explicit command-line input/output arguments documented by `--help`. Integration is not used to compute gene-expression means.
3. Prepare capped myeloid inputs with the `further/01` scripts. The filtered version is used for the exploratory `further/02_run_sctenifoldknk_exploratory.R`. Run `further/03` and `further/04` for summaries and prevalence. `further/05b` invokes the legacy reinforcement script with compatibility adjustments. These are observational network perturbations, not experimental causal evidence.
4. Run `python Revision/revision_analysis.py` for discovery, tissue, and GSE174554 patient-level comparisons; then `reference_diagnostics.py`, `audit_bulk_gene_mapping.py`, `revision_audit.py`, and `final_scientific_checks.py` for the supplementary diagnostics. These require the raw and processed inputs listed below and can rewrite the local derived output directory, so use a fresh clone rather than a frozen submission copy.
5. Run `python Revision/recurrence_marker_reassessment/reassess.py` for paired program-association changes and longitudinal coupling. Cached extraction outputs can be supplied from the supplementary companion folder; removing a cache requests raw-matrix extraction.
6. Run `Rscript Revision/external_validation_expansion_20261008/export_care_siglec1.R` to extract CARE quantities from public raw matrices and original labels. Run `evaluate_external.py`, then `array_validation.py`, then `build_report_and_qa.py` in that directory. All added cohorts and missing mapped-gene outcomes remain in the audit. Cached CARE exports are reused if present; use a new output directory when changing inputs.
7. To benchmark discovery labels, first run `Rscript Revision/export_author_labels.R AUTHOR_WORKSPACE.RData OUTPUT_METADATA_DIR`, then `python Revision/annotation_benchmark.py`. Supply the exported CSV at `JOB34_AUTHOR_WORKSPACE/metadata/GSE200984_author_all_nuclei_metadata.csv`. The RData is about 5.4 GB and may require substantial memory to load. The benchmark matches exact specimen, 16-base barcode and GEM identifier, excluding ambiguous keys. It does not transfer or infer missing author labels.
8. Scientific plots are generated by `further/build_revised_figures.py`, `Revision/revision_figures.py`, `Revision/recurrence_marker_reassessment/make_figure.py` and `Revision/integrated_external_validation_20261008/make_s6.py`. They consume different historical output directories; inspect their declarations before rerunning.

## Environment and scope of reproducibility

The current numerical verification environment uses Python 3.14.6, NumPy 2.4.6, pandas 2.3.3, SciPy 1.16.3 and statsmodels 0.14.6. These are the versions checked for the release, not a claim that every historical preprocessing step used this exact environment. The available CARE session record documents R 4.6.1 and Matrix 1.7-5. Advanced discovery preprocessing additionally requires Scanpy, AnnData, Harmony, infercnvpy, igraph/leiden and compatible NumCodecs/Zarr. The original full historical lockfile is unavailable; those steps have not been clean-room rerun for this release. Current Scanpy 1.12.2, AnnData 0.12.6 and infercnvpy 0.6.1 were found locally, but Harmony is absent from the current verification interpreter. Add-on dependencies are listed separately without invented historical version pins.

Two-sided SciPy `method='auto'` selects the exact, permutation or asymptotic implementation according to version, size, ties and zeros. Wilcoxon uses the default zero handling and no continuity correction; Mann–Whitney uses its default asymptotic continuity correction where applicable. BH families are defined in the manuscript and script, not a study-wide correction. Bootstrap seed 341008 is used for the revised patient-level analyses; original network seeds and their stability checks remain in the scripts.

The repository supports a **context-dependent candidate-marker** interpretation. Tissue-level associations and within-myeloid interferon association do not establish recurrence specificity, prediction performance, or causation. Some historical exploratory outputs are retained for audit rather than promoted to the main claim.
